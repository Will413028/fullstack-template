# Backend — Go

Go modular monolith: stdlib `net/http` with connect-go services generated from the Protobuf contract in `../api`, pgx + sqlc, Atlas declarative schema, opaque sessions in the database, `log/slog`. Decisions and their reasons: `docs/adr/2026-10-18-go-backend.md` (stack, data layer, DB roles) and `docs/adr/2026-10-18-api-and-auth-baseline.md` (topology, auth); the contract: `docs/adr/2026-11-03-api-contract-protobuf-connect.md`.

## Commands

Run from `backend/`. Needs Go (version in `go.mod`) and Docker (integration tests and the Atlas dev database). Tool versions are pinned in `tools/` where Dependabot updates them (Go-built tools in `tools/go.mod`, run as `go tool -modfile=tools/go.mod <name>` so they never change the application's `go.mod`; squawk in `tools/package.json`; diff-cover in `tools/requirements.txt`), and as release binaries with checksums in `Makefile` (golangci-lint, Atlas; hadolint in the root `Makefile`). The weekly Tool versions workflow opens an issue when a release binary falls behind; `python3 scripts/tool_versions.py bump <tool>` (from the repository root) rewrites its version and checksums, Atlas's in `Dockerfile` too, and CI checks the two Atlas pins agree. Never add a tool to `go.mod` itself. A vulnerable dependency of a tool is upgraded in `tools/go.mod`; `make check` shows the tools still produce and detect the same things. CI runs `make check`, so local and CI use the same versions.

```bash
make run                     # serve with backend/.env (format in .env-example)
make test                    # go test -race through gotestsum; integration tests start PostgreSQL 18 with testcontainers
make check                   # everything CI runs: fmt-check gen-check buf-lint lint deadcode test vuln sqlc-diff drift squawk
                             # migrations-immutable api-breaking tools-selftest
make gen                     # regenerate internal/gen from ../api (Connect)
make sqlc                    # regenerate each module's internal/store from its schema.sql and queries
make migration name=<name>   # generate a migration from the modules' schema.sql (Atlas standard build)
make fmt                     # gofmt -w
```

The binary is one command with subcommands: `app serve`, `app migrate` (applies `migrations/` as the owner role, then grants the app role), `app seed-admin`, `app recover-admin` (new password for an existing admin, enabled, sessions ended, throttle cleared: the way back when no admin can sign in), `app healthcheck`. The only enabled admin cannot be disabled or deleted (`auth.ErrLastAdmin`).

## Layout

```
cmd/app/                     # composition root: config, DB pool, services, HTTP server, subcommands
internal/gen/                 # generated Connect and Protobuf code (make gen; never edited)
internal/httpapi/            # Connect handlers, the session cookie, the entry checks (connectEntry), middleware
internal/httpapi/rpc/        # service classes and the admin interceptor, error conversion, paging, update_mask
internal/modules/<m>/        # one module: service (<m>.go), schema.sql, queries/*.sql, sqlc.yaml, internal/store (sqlc)
internal/platform/           # shared lower layer: apperr, authctx, config, db, dbtest, hibp, keyset, logx, migrate
internal/archtest/           # layering checks over the import graph
migrations/                  # generated by Atlas; atlas.sum is its checksum file
atlas.hcl                    # Atlas env: src globs internal/modules/*/schema.sql, auth first
scripts/                     # CI checks: schema drift, immutable migrations, squawk, breaking changes, coverage
```

Modules: `auth` (users, sessions, login throttling, password checks) and `items` (the CRUD example).

## Rules

1. **The contract is the single source.** Services, messages and enums live in `../api` (Protobuf + Connect, `docs/adr/2026-11-03-api-contract-protobuf-connect.md`); lengths and formats are checked once, in the module's service (decision D2), which `seed-admin` and `recover-admin` call too. Do not repeat a limit in a handler or zod. After changing the contract run `make gen` here and `pnpm gen:api` in `frontend/`; CI fails when either generated tree differs. `make buf-lint` and `make api-breaking` (buf, against `origin/main`) check the contract.
2. **Layering** (depguard in `.golangci.yml`, `internal/archtest`): `internal/modules/<m>` never imports `net/http`, `internal/httpapi`, `cmd` or another module; `internal/platform` imports neither modules nor `internal/httpapi`. Handlers translate between generated types and module types in `internal/httpapi`. The current user reaches modules through `internal/platform/authctx`.
3. **Errors.** Services return `*apperr.Error` (a kind plus a stable `code`) for expected failures and plain errors for everything else. `internal/httpapi/rpc` (`Convert`) is the only place that turns them into Connect errors (a code, `ErrorInfo.reason`, `BadRequest` field violations, `RetryInfo`); every reason must be declared in `app.common.v1` (`TestEveryAppErrCodeIsDeclared` reads the code of every `apperr.New` and `apperr.Invalid` call and `apperr.Error` literal from the source; a code assigned later is not seen). Unexpected errors become `internal` whose details stay in the log. Handlers do not build Connect errors or choose codes for failures.
4. **SQL only through sqlc.** Every query is in `internal/modules/<m>/queries/*.sql`; `make sqlc` generates `internal/store`. A hand-written pgx `Query` fails lint (forbidigo): generated code is what closes the rows and checks `rows.Err`. A module's queries never select from or join another module's tables; the only cross-module foreign key is to `users`.
5. **Schema only through Atlas.** Edit the module's `schema.sql`, then `make migration name=<name>`. DDL is hand-written only to replace a generated change that squawk flags for locking with lock-free steps (`NOT VALID`, then `VALIDATE CONSTRAINT` in the next file), and `make drift` must still pass; a pure data backfill is the other hand-written migration. Both use `atlas migrate new`. Every migration keeps the previous release working (the deploy runs it before replacing the backend, and rollback runs the old image on the new schema): a structure the old code uses is removed or reshaped only in the release after the code stops using it (expand, then contract; `docs/rules/database-design.md`), and squawk enforces it. Every foreign key to `users` cascades or sets null, so deleting an account removes what it owns (`TestForeignKeysToUsersAllowDeletion`). Migrations merged into `main` never change (`make migrations-immutable`); squawk checks locks (`make squawk`). Database rules: `docs/rules/database-design.md`.
6. **Authorization in queries.** A user-owned resource's queries always carry the owner condition, so another user's row is `not_found`, never `permission_denied`. Who may call a service follows its name: `<Module>PublicService` anyone, `<Module>AppService` a signed-in user, `<Module>AdminService` an admin (`internal/httpapi/rpc`); a service named otherwise stops the server from starting. Anonymous App and Admin calls are refused before the request is decoded (`connectEntry`); the admin interceptor rejects non-admins.
7. **Every resource can be read back.** A Create or Update returns the resource, and its service package has a `Get<Resource>` (AIP-121, 133, 134; `TestConnectServicesReturnTheirResources`). Partial updates take an `update_mask` (`rpc.UpdatePaths`); lists take `page_size` and `page_token` (AIP-158, `rpc.PageRequest`). API rules: `docs/rules/api-design.md`.
8. **Sessions.** Sign-in is throttled per account and client (address, or a trusted device from the `__Host-device` cookie); clients without a trusted device share an account-wide limit of 100 failures (`auth/devices.go`). The session cookie is `HttpOnly` (`__Host-session`, or `session` when `COOKIE_SECURE=false`); `http.CrossOriginProtection` wraps the whole mux. A feature that changes a user's role or password must revoke all of that user's sessions.
9. **Time.** Code reads the time from the injected clock (`auth.Config.Now`, `httpapi.Deps.Now`); only `cmd/` and tests call `time.Now`, `time.Since` or `time.Until` (forbidigo). Resource tables' `created_at`/`updated_at` come from the database's `now()` (`docs/rules/database-design.md`, 時間戳記).
10. **Tests.** Behavior is tested through the generated Connect clients against a real PostgreSQL (`internal/platform/dbtest`, testcontainers) with the same DB roles as production. Follow `internal/httpapi/items_test.go`. Every package with tests has a `TestMain` that fails on a leaked goroutine: `dbtest.Main` for database tests, `goleak.VerifyTestMain` otherwise (`internal/archtest` checks this). `make deadcode` fails on a function that neither the binary nor a test reaches.
11. **Audit.** A state-changing admin operation writes one `audit_events` row in its own transaction (`auth.Service.audit`); `TestAdminChangesAreAudited` fails for a new one without a case. A table whose `schema.sql` comment is `append-only` (optionally `: retain N days by <column>`) gets INSERT and SELECT only for the app role, and `app migrate` prunes it. Security events (sign-in, sign-out, refused operations) are log lines with `event` and `user_id`.

## Adding a module

Use `/add-module <name>` (empty skeleton) or `/add-crud <entity> --fields "..."` (full CRUD resource); both follow the `items` module. The steps: the service, its messages and comments with the limits in `../api/app/<module>/v1/<module>.proto`, `schema.sql` (Atlas picks it up by glob), queries and `sqlc.yaml`, the module service (`internal/modules/<m>`, where the limits are checked), the Connect handlers in `internal/httpapi` and their entry in `connectServices`, wiring in `cmd/app/main.go`, then `make gen sqlc migration name=<name>`, `pnpm gen:api` in `frontend/`, tests through the generated client, and `make check`.
